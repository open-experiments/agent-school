Syllabus upgrade: blueprint-wise and hands-on

BLUEPRINT-WISE

One SYLLABUS.md that ties the courses to the article

  • Component × course matrix: model, harness, skills, capabilities, governance, state, observability, evaluation, data pipeline
  • Learning objectives per course and a prerequisites graph
  • Decision guides: which harness, which capability pattern (1 thin client, 2 service, 3 batch Job), when RAG, a classic model as a tool, when a judge, which rail forces which safe state
  • Glossary: skill and capability as the 4xx series defines them; the shipped courses keep their wording, with their deviations recorded here instead of patched

HANDS-ON

A fourth lab tier: modify

  • Today: replay in the portal, run offline on a laptop, deploy on a cluster
  • Add exercises with a checker: add and register a skill; call it from the wrong identity and capture the 403; swap the retriever; tighten a gate and capture the audited override
  • The CI evidence gate (discussion #21) is the checker, so exercises and CI are one investment
The blueprint mapping exists per course and in the roadmap, and nothing ties it together for a learner. The syllabus adds objectives, the matrix and the decision guides a solution architect needs. On the hands-on side the labs stop at deploy; the modify tier makes the learner change the system and prove it with the same evidence gate the repo uses.
