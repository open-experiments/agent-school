401 Skills and capabilities

Skill catalog

  • One SKILL.md per role
  • Frontmatter: role, risk class, prescribed capabilities, offline episode
  • Governed as content: review, version, provenance, a judge
  • Portable across harnesses; the OpenClaw track regains its procedure

Capability catalog

  • A manifest per MCP server: backend pattern 1/2/3, I/O schema, risk class, allowed identities, rate class, data class
  • Generates the registry, per-agent allow-lists, Kuadrant AuthPolicy and RateLimit
  • One source for the six copies of 301’s playbook catalog

Selection, two layers

  • Procedure per problem class: role level, mostly static, routed by class as the library grows
  • Capability per step: the skill prescribes it; cheap reads first, actuation last
  • Which skill, which capability, and why: recorded in the trace

THE FIRST PLATFORM-LAYER COURSE, PROVEN ON THE SHIPPED ONES

101, 301 and 302 consume the registry exactly as shipped. Their deviations today (procedures in prompts and Python, 202 and 301 reads outside MCP, six copies of one catalog) are recorded in the syllabus, with no patches to their code, tapes or videos.

4xx is the platform layer: each course builds one cross-workload component and proves it against the existing courses as consumers, without modifying them. 401 is the first. The skill catalog carries procedure and is reviewed like code. The capability catalog is a manifest per MCP server, and a generator turns it into the registry and the gateway policies, the way the tape generator turns manuals into labs. Selection splits into two questions with different mechanisms, and both answers land in the trace.
